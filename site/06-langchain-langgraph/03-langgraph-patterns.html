LangGraph Patterns: Subgraphs, Human-in-the-Loop, Streaming

16 min listen · Three production patterns built on the LangGraph board: boards hidden inside squares (subgraphs and their persistence modes), a red square that freezes the game for a human (interrupt and Command resume), and a broadcast booth that streams every move live (stream modes and the newer event-streaming projections).

Facts verified: 2026-09-25 (langgraph 1.2.12; event streaming version="v3" introduced in 1.2, unified version="v2" stream/invoke format in 1.1)

One-sentence thesis

Subgraphs, interrupts and streaming all ride on the checkpoint layer: a subgraph is a graph used as a node (with its own checkpoint namespace), interrupt() is a checkpoint-and-stop that resumes via Command(resume=...) by re-running the node from the top, and streaming exposes the super-step machinery live — with private state leaking unless you restrict it.

Code

Interrupt + resume (raw LangGraph):

from langgraph.types import interrupt, Command
from langgraph.graph import END

def approve_refund(state):
    # DON'T send emails / create tickets here — this code runs again on resume
    decision = interrupt({"action": "refund", "amount": state["amount"],
                          "customer": state["customer_id"]})
    if decision["type"] == "approve":
        return Command(goto="issue_refund")
    return Command(update={"note": decision.get("reason", "")}, goto=END)

graph = builder.compile(checkpointer=postgres_saver)   # persistent checkpointer required
cfg = {"configurable": {"thread_id": "cust-77:refund-3"}}

stream = graph.stream_events({"amount": 400, "customer_id": "c77"}, config=cfg, version="v3")
for msg in stream.messages:
    print(msg.text, end="")
if stream.interrupted:
    payload = stream.interrupts            # show to a human
    stream = graph.stream_events(Command(resume={"type": "approve"}), config=cfg, version="v3")

Anti-patterns (from the "rules of interrupts"):

try:                          # BAD: bare except swallows the pause exception
    ok = interrupt("approve?")
except Exception:
    ok = True                 # -> action runs unapproved

while True:                   # BAD: every resume replays all previous iterations
    age = interrupt("age?")
    if valid(age): break

Tradeoffs to volunteer

  1. Re-execution on resume — code before interrupt() runs twice → duplicate emails/tickets unless idempotent or moved after/into a separate node. Applies at both levels with subgraphs.
  2. Swallowed pause — bare try/except around interrupt() lets the action run without approval.
  3. Order-indexed resume values — never conditionally skip or non-deterministically loop interrupts; validate with one interrupt per visit + conditional edge back.
  4. Private state leaks in values streaming — restrict with output_keys, prefer updates/messages to clients, filter server-side.
  5. Per-thread subgraphs + parallel tool calls — checkpoint collisions; disable parallel calls or use ToolCallLimitMiddleware.
  6. Pending approvals are an ops queue — notify, alert on age, define expiry behavior; requires a persistent checkpointer.

5 interview questions

Q1. How does LangGraph human-in-the-loop work mechanically? interrupt(payload) raises a special exception caught by the runtime, which checkpoints state and returns the payload to the caller; the graph is frozen in the checkpointer, no process held. Resume with Command(resume=value) on the same thread_id; the node re-runs from its start and interrupt() returns the value.

Q2. Two production bugs with interrupts and their fixes? Duplicate side effects (non-idempotent code before interrupt() re-runs) → make idempotent, move after, or split nodes. Unapproved actions (bare try/except swallowing the pause) → catch specific exceptions only, keep interrupt outside error handling.

Q3. When and how do you use subgraphs? For reuse, multi-agent specialists with private histories, and team boundaries. Shared keys → add compiled subgraph as node; different schemas → call it in a wrapper node. Persistence: per-invocation default; per-thread for memory across calls (no parallel calls); stateless when no pause/durability needed.

Q4. Which stream mode would you use for a chat UI, and what's new? messages for token-by-token output (with node/model metadata), plus updates or custom for step/tool progress. LangGraph 1.1 unified chunks as {type, ns, data}; 1.2's event streaming (version="v3") offers typed projections including stream.interrupts and stream.interrupted, recommended for new apps.

Q5. What security issue can streaming introduce? values streaming emits all state channels including private ones not in the output schema — internal reasoning or sensitive records can reach the client. Restrict with output_keys, stream only messages/updates, and tag internal model calls nostream.

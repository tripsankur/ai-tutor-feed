8 Prod checklist Postgres checkpointer (not in-memory), opaque thread IDs, durability mode, idempotent side effects, reducers, checkpoint retention, recursion limit/retries/timeouts E2

Same format as always: I ask, you answer out loud in the pause, then I give you a strong answer to compare. Ordered roughly as the track ran. Ready. [PAUSE 2s] Question one. What is a Runnable, and why does it matter? [PAUSE 6s] Strong answer: a Runnable is the one standard interface every LangChain component implements — invoke, batch, stream, and their async versions, plus a shared config for callbacks, tags, and limits. Because prompts, models, parsers, retrievers, and even compiled graphs all share it, they compose with the pipe operator, and the composed pipeline gets streaming, batching, async, and tracing for free. [PAUSE 2s] Question two. Chain or agent — how do you decide? [PAUSE 6s] Strong answer: it comes down to who decides the control flow. A chain has a fixed path chosen at design time, so latency and cost are predictable. An agent lets the model choose tools in a loop at run time, which is flexible but brings variable cost and runaway loops. Default to the fixed pipeline, escalate to an agent only when the path genuinely depends on the input, and always cap the loop. [PAUSE 2s] Question three. What changed in LangChain version one? [PAUSE 6s] Strong answer: the core narrowed to agents, models, messages, and tools. Create agent replaced the old agent classes and LangGraph's prebuilt react agent, and it runs on LangGraph underneath. Middleware became the way to customize the loop, standard content blocks unified message content across providers, and legacy chains and the agent executor moved into the langchain classic package, with a promise of no breaking changes until version two. [PAUSE 2s] Question four. Name the middleware hooks and give two uses. [PAUSE 6s] Strong answer: before agent, before model, wrap model call, wrap tool call, after model, and after agent. Typical uses: summarizing long conversation history before the model call, redacting personal data, pausing for human approval on sensitive tool calls, retries, and model or tool call limits to stop runaway loops. [PAUSE 2s] Question five. Why use LangGraph instead of a while loop around the model? [PAUSE 6s] Strong answer: a while loop keeps state in memory, so a crash, a deploy, or a human pause loses everything. LangGraph makes state explicit and checkpoints it at every super-step into a persistent store keyed by thread I D. That gives resume after failure, conversation memory, pauses that can last days, and time travel for debugging, plus reducers that make parallel branches safe. [PAUSE 2s] Question six. Walk through how LangGraph executes a graph. [PAUSE 6s] Strong answer: Pregel-style super-steps. In each step, all active nodes run in parallel and return partial state updates; the updates are merged through per-key reducers; then fixed or conditional edges pick the next active nodes. A checkpoint is written at each super-step boundary, and the run ends when no nodes are active, or fails at the recursion limit. [PAUSE 2s] Question seven. What is a reducer, and what goes wrong without one? [PAUSE 6s] Strong answer: a reducer is the per-key merge rule for state — replace, append, or the special add messages rule that appends and updates by message I D. Without one, a key defaults to last write wins, so two parallel branches writing the same key either clobber each other's results or raise an invalid update error. [PAUSE 2s] Question eight. What would you check before putting a LangGraph agent in production? [PAUSE 6s] Strong answer: a persistent checkpointer such as Postgres, never the in-memory one. Opaque per-user thread I Ds. A deliberately chosen durability mode. Idempotent side effects, since nodes re-run from the top on resume. Reducers on every key parallel branches write, a retention policy for checkpoint growth, and explicit recursion limits, retries, and timeouts. [PAUSE 2s] Question nine. How do you add human approval before a sensitive action? [PAUSE 6s] Strong answer: with a persistent checkpointer, call interrupt inside the node, or put the human-in-the-loop middleware on specific tools. The state is saved and the payload goes to the caller; the decision comes back as a Command with a resume value on the same thread I D. The node re-runs from its start, so anything before the interrupt must be idempotent, and never wrap the interrupt in a broad try-except, because that swallows the pause. [PAUSE 2s] Question ten. When would you use a subgraph, and how do you wire it in? [PAUSE 6s] Strong answer: for reuse, for multi-agent systems where each specialist has its own loop and private history, and for team ownership boundaries. If the subgraph shares state keys with the parent, add the compiled subgraph directly as a node; if not, call it inside a wrapper node that maps state in and out. A subgraph can also send a Command to the parent graph to hand control back. [PAUSE 2s] Question eleven. How do you stream an agent's output to a user? [PAUSE 6s] Strong answer: choose stream modes by consumer — messages for token-by-token chat, updates for step-by-step progress, custom for tool progress events, and values for the full state. And be careful: streaming full values can expose private state keys to the client, so filter what leaves the server. [PAUSE 2s] Question twelve. In LangSmith, what are a run, a trace, a thread, and a project? [PAUSE 6s] Strong answer: a run is one unit of work — a model call, a tool call, a graph node — the equivalent of an OpenTelemetry span. A trace is the tree of runs for one request, a thread links the traces of a multi-turn conversation, and a project is the container for one application or environment. And LangSmith does not require LangChain: plain code can use the traceable decorator, and it ingests OpenTelemetry. [PAUSE 2s] Question thirteen. How do you evaluate an agent, offline and online? [PAUSE 6s] Strong answer: offline, keep a versioned dataset of examples, seeded by hand and grown from production failures, and run every candidate as an experiment scored by code checks first, L L M judges for fuzzy criteria, and human annotation to calibrate the judges; compare row by row, not just averages. Online, run reference-free evaluators on sampled production traces and route low scores into annotation queues and back into the dataset. Watch the bill: pricing is per trace, and feedback upgrades a trace to extended retention. [PAUSE 2s] Question fourteen. When would you not use LangChain or LangGraph? [PAUSE 6s] Strong answer: stand on the lowest step of abstraction that holds the problem. A single structured-output call or a simple retrieval pipeline needs no agent framework; a simple single-provider tool loop may fit that provider's agent S D K. LangGraph earns its place with branching flow, long-lived state, human approval, and replay, and for days-long workflows with irreversible side effects, add a durable execution engine like Temporal underneath. Either way, keep business logic in plain functions so the framework stays replaceable. [PAUSE 2s] That's the drill.

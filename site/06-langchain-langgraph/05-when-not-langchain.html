Track 6 · LangChain / LangGraph · Episode 5

When NOT LangChain — Tradeoffs & Alternatives

16 min listen · A staircase of abstraction from the raw model A P I up to managed agent platforms: what each step gives you for free, what it takes away, where LangChain and LangGraph sit on it, and how to pick the lowest step that holds your problem.

Facts verified: 2026-09-25

One-sentence thesis

"LangChain" is not one thing: it spans a thin provider-neutral toolbox, an agent loop (create_agent), a graph runtime (LangGraph), and a managed platform (LangSmith Deployment). The senior skill is standing on the lowest level of abstraction that holds your problem, and keeping business logic in plain functions so you can move later.

The mental image: the staircase

Five steps rising left → right. Up = convenience, down = control. A steel beam (durable execution) runs underneath all of them.

flowchart LR
    S1["1. Raw model API (provider SDK, own loop)"] --> S2["2. Thin helpers (routing, schemas, retries) + langchain-core and integrations"]
    S2 --> S3["3. Agent loop frameworks (OpenAI Agents SDK, Claude Agent SDK, Pydantic AI, LangChain create_agent)"]
    S3 --> S4["4. Graph runtimes (LangGraph, Microsoft Agent Framework workflows, Google ADK)"]
    S4 --> S5["5. Managed platforms (LangSmith Deployment, cloud agent services, Agent Bricks)"]
    B["Steel beam: durable execution engine (Temporal) under any step"]
    B -.-> S3
    B -.-> S4

Where each LangChain piece sits

Piece Step What it is (v1, Oct 2025+)
langchain-core + integration packages 2 Messages (standard content blocks), runnables, chat model / tool interfaces, hundreds of provider integrations
langchain.agents.create_agent + middleware 3 Agent loop built on LangGraph; hooks before/after model call and around tool calls; prebuilt summarization, human-in-the-loop, PII middleware. Replaces LangGraph's deprecated create_react_agent

"We stopped using LangChain" → ask which step. Often it means the legacy chains, not LangGraph.

The raw loop (step 1) — what you own

import anthropic
client = anthropic.Anthropic()

def run_agent(messages, tools, tool_impls, max_turns=10):
    for _ in range(max_turns):                       # budget guard
        resp = client.messages.create(
            model="claude-sonnet-4-5", max_tokens=2048,
            tools=tools, messages=messages,
        )
        messages.append({"role": "assistant", "content": resp.content})
        if resp.stop_reason != "tool_use":
            return resp
        results = []
        for block in resp.content:
            if block.type == "tool_use":
                out = tool_impls[block.name](**block.input)   # plain functions
                results.append({"type": "tool_result",
                                "tool_use_id": block.id, "content": str(out)})
        messages.append({"role": "user", "content": results})
    raise RuntimeError("turn budget exceeded")

~40 lines. Everything else — streaming, retries/backoff, persistence, tracing, token budgeting, provider portability — is now yours.

Framework-agnostic architecture (keeps you mobile on the staircase)

# domain/tools.py — plain functions, plain types; no framework imports
def lookup_order(order_id: str) -> dict: ...
def issue_refund(order_id: str, idempotency_key: str) -> dict: ...  # idempotent side effect

# adapters/langchain_agent.py — thin layer
from langchain.agents import create_agent
from langchain.tools import tool
from domain import tools as d

agent = create_agent(
    model="anthropic:claude-sonnet-4-5",
    tools=[tool(d.lookup_order), tool(d.issue_refund)],
    system_prompt="You are a support agent...",
)

Swap the adapter (OpenAI Agents SDK, Pydantic AI, raw loop) without touching domain/.

Checkpoints vs durable execution

flowchart TB
    subgraph LG["LangGraph checkpointer"]
        A["Node A done"] --> C1["checkpoint"] --> B["Node B (mid-run crash)"]
        B -.->|"resume re-runs whole node B"| C1
    end
    subgraph T["Durable execution (Temporal)"]
        E["Event history of every activity"] --> R["Deterministic replay + activity retries/timeouts"]
    end
  • LangGraph calls its checkpointing "durable execution" (durability modes; resume after crash) — true at node granularity. The checkpointer saves state between nodes (super-step boundaries), not inside a node. A node with side effects (charge card, send email) can double-execute on resume.
  • Temporal = event history + deterministic replay; built for workflows lasting days. Temporal ships a LangGraph plugin (graph as workflow, nodes as activities).
  • Rule of thumb: pauses for hours/days, several external side-effecting calls, or must-never-double-execute → add durable execution underneath and make tools idempotent regardless.

Tradeoffs with numbers

  • Latency overhead: framework Python overhead ≈ single-digit ms vs model calls of hundreds of ms to tens of seconds → a weak argument either way.
  • Debuggability: framework-built prompts ≠ your template (hidden system text, history truncation defaults). Always inspect exact messages sent (tracing).
  • Dependency churn: pre-v1 import-path churn was a real tax; v1 promises no breaking changes until 2.0, but integration surface still means more transitive deps/CVEs.
  • Abstraction mismatch: unusual topologies, custom streaming protocols, long-lived connections → you fight the framework. Middleware is LangChain's escape hatch.
  • Counterweight: fully custom teams often build "a worse LangGraph" — no checkpoints, no replay, no debugger, one owner (bus factor 1).

5 interview questions

Q1. What do you think of LangChain? Separate the pieces. Core + integrations = useful provider-neutral toolbox. Legacy chains hid prompts and churned APIs; v1 moved them to langchain-classic. LangGraph is the part to defend in production (state, checkpoints, interrupts, replay). Pick the lowest abstraction that fits.

Q2. When would you not use any framework? Single structured-output calls, simple pipelines, or when you need a brand-new provider feature on day one and full visibility into every token. The raw loop is ~40 lines; you then own streaming, retries, persistence, and tracing.

Q3. Would you build an in-house agent framework? Only the thin parts. Keep tools/business logic as plain functions so the orchestration layer is swappable; adopt a graph runtime once you need persistence, interrupts, or multi-agent coordination — homemade state machines become a liability when their author leaves.

Q4. LangGraph vs Temporal? Different layers. LangGraph: agent-shaped state, checkpoints between nodes, interrupts, streaming. Temporal: durable execution via event history, deterministic replay, activity retries, days-long workflows. LangGraph resumes at node granularity; Temporal replays per activity — for irreversible side effects run the graph on a durable engine or at least make tools idempotent.

Q5. How do you avoid framework lock-in? Architect for it: domain logic, tools, retrieval as plain functions with plain types; the framework is a thin adapter. Use OpenTelemetry-compatible tracing. Keep prompts and eval datasets in your own storage. Then moving up or down the staircase swaps the adapter, not the system.

Temporal gives durable execution with event-history replay and activity retries for workflows lasting days. LangGraph resumes at node granularity from its last checkpoint; Temporal replays an event history at the level of each individual activity. For long-running flows with irreversible side effects, I would run the graph on top of a durable engine, or at minimum make every side-effecting tool idempotent." On the floor, the raw model A P I: total control, total transparency, and you own everything — streaming, retries, persistence, tracing. Step two, thin helpers: routing, schemas, retries. Your loop, fewer chores. LangChain's core vocabulary and integration toolbox live here, and you can carry that toolbox to any step. Step three, agent loop frameworks: OpenAI Agents S D K, Claude Agent S D K, Pydantic A I, LangChain's create agent. The loop is theirs; you bring model, instructions, tools. Provider-native kits trade portability for depth. Step four, graph runtimes: LangGraph, Microsoft Agent Framework, Google's A D K. Explicit state, checkpoints, interrupts, replay. Worth it when control flow and time matter; overkill for a two-step pipeline. Step five, managed platforms: someone else runs it, you pay in money and lock-in. Underneath, the steel beam: durable execution, for days-long workflows with side effects, because node-level checkpoints can re-run a side effect that a finer-grained engine would not.

Planning & Reasoning Patterns: CoT, Reflection, Plan-Execute

18 min listen · Chain of thought, plan-and-execute, and reflection, built as a planner's room, a sealed room with a private chalkboard, and an inspector's booth. Includes how modern reasoning models with adaptive, effort-controlled thinking absorb some of these patterns and make others more valuable.

Facts verified: 2026-09-25

One-sentence thesis

Planning and reasoning patterns are choices about where thinking happens (visible output vs. a reasoning model's private, billed thinking), when the route is decided (step-by-step ReAct vs. up-front plan with replanning), and what checks the work (grounded verifiers vs. ungrounded self-critique). Reasoning models absorb much short-horizon CoT and planning, and make grounded verification more valuable.

The mental image: three rooms in a row

  • Left — planner's room (drafting table): goal → numbered steps.
  • Center — the sealed room (worker) from episode 1, now with a chalkboard on the back wall = a reasoning model's private thinking.
  • Right — inspector's booth (magnifying glass, red pen): critique / verify.
  • Backward arrows: inspector → worker = "revise"; worker → planner = "replan".
flowchart LR
    G["Goal"] --> P["Planner room: numbered plan"]
    P --> W["Worker room (model + chalkboard = private thinking)"]
    W --> I{"Inspector booth: tests, validators, evidence, rubric"}
    I -->|pass| OUT["Output"]
    I -->|"revise (cap 2-3 rounds)"| W
    W -->|"replan on error / empty / surprising result"| P
    EXT["External signal: unit tests, schema, SQL result, retrieved docs"] -.-> I

Pattern cheat sheet

Pattern Mechanism Wins Loses Reasoning-model era verdict
Chain of thought (Wei et al. 2022; "let's think step by step", Kojima et al. 2022) Write intermediate steps → more serial compute, readable trail Multi-step problems on non-reasoning models Visible, costs output tokens, parse answer out Redundant for reasoning models; still useful for small/fast models or when visible rationale needed
Self-consistency (Wang et al. 2022) Sample N chains, majority vote Reliability on single-answer tasks N× cost Niche; use where answer is checkable and stakes high
Tree of thoughts (Yao et al. 2023) Branch, evaluate, search/backtrack Puzzle-like search Very expensive, complex Rarely worth it in production agents
ReAct Think → act → observe, one step at a time Adaptive Myopic, frontier model every step Native tool calls + interleaved thinking = default for short tasks
Plan-and-execute / ReWOO (Xu et al. 2023) Plan up front (placeholders), workers fill, solver combines ~5× token efficiency on HotpotQA (paper), parallel, approvable Plans go stale Use for long horizons, fan-out, approval gates, cost routing; always add replanning
Reflection / evaluator-optimizer; Reflexion (Shinn et al. 2023) Generate → critique → revise; store verbal lessons across trials Big gains with external signal Ungrounded self-critique small or negative gains (Huang et al. 2023) Ground the inspector; cap rounds

Reasoning models — mechanics that matter (verified 2026-09-25)

  • Thinking tokens are billed as output tokens even when hidden or summarized; billed count ≠ visible count.
  • Effort, not budgets: Anthropic output_config.effort (low / medium / high / xhigh / max, availability varies by model); legacy budget_tokens still works on older models but is not recommended. OpenAI reasoning.effort ladder is model-dependent (values may include none, minimal, low, medium, high, xhigh).
  • Adaptive thinking: model decides per request whether/how much to think — don't assume every turn has a thinking block. In a tool loop, the first call after user input usually carries most thinking.
  • Interleaved thinking: thinks between tool calls (automatic with adaptive thinking on current Claude models).
  • Pass reasoning back: return thinking blocks (Anthropic) / reasoning items incl. encrypted_content for stateless/ZDR (OpenAI Responses) unmodified during tool loops.
  • Caching: changing effort between requests can invalidate prompt-cache breakpoints — hold effort constant per conversation; steer per-turn with message wording.
  • Prompting: give goals, constraints, success criteria; don't prescribe "think step by step".
  • Faithfulness: visible reasoning is evidence, not a guaranteed faithful audit log.

resp = client.messages.create(

)
print(resp.usage)  # output_tokens includes thinking; see output_tokens_details.thinking_tokens

    include=["reasoning.encrypted_content"],

Plan-and-execute with replanning (pseudo)

plan = planner(goal)                         # big model, once
for step in plan:
    result = executor(step)                  # small model / tool
    if result.error or result.empty or surprising(result):
        plan = planner(goal, done_so_far, result)   # replan trigger
final = verify(solver(results))              # grounded check before shipping

Routing heuristic

Task shape Pattern
Lookup / extraction / routing Fast non-reasoning model, no planner
Multi-step with tools, < ~10 steps Reasoning model + interleaved thinking, moderate effort (ReAct-style)
Long horizon, parallelizable, or needs human approval Explicit planner + replanning triggers
Checkable output (code, SQL, schema) Add grounded inspector (tests/validators), cap 2–3 rounds

Pitfalls / war stories

  1. Stale plan — table renamed, tool returned empty (not error), executor kept going, report said "churn 0%". Fix: tools error loudly, replan on empty/surprising results, grounded final check.
  2. Uncapped critic loop — same-model critic always finds something; 8 rounds, blander text, lost a key detail, 8× cost. Fix: cap 2–3, concrete rubric, ground truth, keep best-scoring draft.
  3. Effort thrash — toggling effort per turn breaks prompt cache.
  4. Stripping thinking blocks in tool loops → model loses reasoning behind its own calls.

Key terms

Term Meaning
Chain of thought Intermediate reasoning written as tokens
Reasoning model Model trained (largely RL) to think at length before answering
Effort Soft control over how much the model thinks/outputs
Adaptive thinking Model decides per request whether to think
Interleaved thinking Thinking between tool calls
Plan-and-execute Explicit plan then execution; ReWOO uses placeholders
Replanning Revising the plan on triggers
Evaluator-optimizer Generator + evaluator loop
Reflexion Verbal lessons stored across attempts
Grounded verification Critique backed by external signal

5 interview questions

Q1. Why does chain of thought improve accuracy? Each token gets roughly fixed compute; writing intermediate steps buys more serial computation and creates intermediate results the model reads back. Reasoning models internalize this as private thinking billed as output tokens.

Q2. How do reasoning models change your prompting and architecture? Don't prompt "step by step" — specify goals, constraints, success criteria. Control depth with effort, expect adaptive (sometimes zero) thinking, pass thinking/reasoning items back during tool loops, keep effort stable for caching. Many short tasks no longer need an explicit planner.

Q3. ReAct vs plan-and-execute? ReAct: adaptive, myopic, frontier model every step. Plan-and-execute: cheaper (big model plans, small models execute), parallel, human-approvable, but stale plans — add replanning triggers. Use a planner for long horizons, fan-out, approval gates, cost routing.

Q4. Does self-reflection work? With external signal (tests, compilers, validators, evidence, different judge) — yes, strongly. Same-model critique without new information: small or negative gains. Ground it, rubric it, cap at 2–3 rounds, keep best draft.

Q5. How would you pick reasoning effort for a production agent? Start at the model's default/moderate level, measure quality, latency, and cost on a representative traffic sample, raise effort only on task classes where quality gains justify it, and route simple requests to fast non-reasoning models. Keep effort constant within a conversation.

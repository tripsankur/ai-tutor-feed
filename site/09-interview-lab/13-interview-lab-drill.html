Micro vs macro F1 — quick worked check

from sklearn.metrics import f1_score
y_true = [0]*90 + [1]*8 + [2]*2
y_pred = [0]*90 + [1]*8 + [0]*2          # rare class 2 always missed
f1_score(y_true, y_pred, average="micro")  # 0.98  (= accuracy)
f1_score(y_true, y_pred, average="macro")  # ~0.66 (class 2 F1 = 0)

[PAUSE 6s] Strong answer: an A P I layer that authenticates, validates, counts real tokens, masks personal data, and rate-limits each tenant in tokens per minute, with deadlines and cancellation that propagate down. [PAUSE 2s] Question two. How does the K V cache work, and how is it managed? [PAUSE 6s] Strong answer: during decoding, each new token attends to every earlier token, so instead of recomputing their keys and values every step, the engine stores them — per layer, per K V head — roughly a hundred and twenty-eight kilobytes per token for an eight-billion-parameter model. v L L M manages it like virtual memory: fixed-size blocks allocated on demand, tracked in a block table, shared across identical prefixes, evicted least recently used. When memory runs out, the newest request is preempted and later recomputed, and a steady preemption rate means you're admitting more than the cache can hold. [PAUSE 2s] Question three. What do max num seqs and max num batched tokens control, and how do you tune them? [PAUSE 6s] Strong answer: max num seqs caps how many sequences run concurrently in a batch; max num batched tokens caps how many tokens the scheduler processes in one step, shared between decodes and prefill chunks. A smaller token budget protects inter-token latency, a larger one improves time to first token and throughput. I set max model len from real traffic, then sweep both parameters under a realistic load test, watching preemptions, and pick the point with the best goodput. [PAUSE 2s] Question four. How did you set up the horizontal pod autoscaler, and how did you pick the scaling parameters? [PAUSE 6s] Strong answer: not on C P U, and not on G P U utilization, which reads near a hundred percent whenever anything is running. I scaled on requests waiting in the engine queue, with K V cache usage as a second signal, exported through Prometheus and fed in with an adapter or Keda. The H P A computes desired replicas as current replicas times the metric over the target; scale up fast, scale down slowly with a stabilization window, keep a warm minimum because cold starts take minutes, and set the target below the knee found by load testing one replica. [PAUSE 2s] Question five. Which latency metrics did you measure, and why those? [PAUSE 6s] Strong answer: time to first token, because in a streaming interface that's the silence the user feels — queueing plus prefill. Distillation versus quantization: advantages and disadvantages. [PAUSE 6s] Strong answer: distillation trains a smaller student model on a teacher's outputs or probabilities; it cuts compute and latency substantially, but it's a real training project and the student has a lower capability ceiling. Quantization stores the same model's weights, and sometimes activations, in fewer bits which is quick, cheap and reversible, but damage hides in long contexts, numbers and structured outputs. They stack: distil, then quantize, then evaluate on your hardest slices before any customer sees it. [PAUSE 2s] Question eight. Why do L L Ms repeat sequences, and how do you mitigate it? [PAUSE 6s] Strong answer: generation conditions on everything already written, and attention has a strong copying mechanism, so once a phrase repeats, repeating it again becomes more likely — a self-reinforcing loop, worse with greedy decoding and long outputs. Mitigations: moderate temperature, gentle frequency or repetition penalties for prose but not for extraction, length caps and correct stop sequences, and a monitoring alarm on the rate of outputs that hit the length cap. [PAUSE 2s] Question nine. How do you handle hallucinations in a regulated setting? [PAUSE 6s] Strong answer: layers. [PAUSE 2s] Question eleven. In R A G, how do you handle document version changes — edited sections, removed sections, and keeping the index consistent? [PAUSE 6s] Strong answer: give each section a stable identifier and a content hash, and keep a manifest ledger mapping sections to versions and chunk I Ds.

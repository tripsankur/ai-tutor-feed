Why LLMs Repeat Themselves & Handling Hallucinations

18 min listen · The writer's table: tiles laid left to right, a mirror that reflects everything already written, a dial panel for decoding, a stack of sources, and three gates on the way out. Why models fall into repetition loops, which knobs actually break them, and a layered defense against hallucination for regulated outputs.

Facts verified: 2026-09-25

Thesis: Repetition and hallucination come from the same autoregressive loop. Repetition happens when the model's own output reinforces itself (a self-reinforcing copy loop that greedy decoding can't escape). Hallucination happens when the most plausible next token isn't the true one. So fix the mechanism (pipeline, decoding, grounding), know the side effects of each knob, and add layered verification for regulated outputs.

Interview questions (as asked): "Why do LLMs sometimes repeat the same sequence, and how do you mitigate it?" and "How do you handle hallucinations?"

Part 1: why models repeat

Cause Mechanism
Self-reinforcement Probability of repeating a sentence rises almost monotonically with the number of times it's already in context (Xu et al., NeurIPS 2022)
Greedy / very low temperature, beam search Maximization decoding → bland, looping text (Holtzman et al., nucleus sampling paper); no randomness to exit the loop
Induction heads Prefix-match-and-copy circuit: "what came after this last time?" Research links induction-head dominance to the "repetition curse"
Long outputs / long contexts More material to copy; more chances for a phrase to become top choice at its own restart point
Repetitive inputs Flattened tables, logs, boilerplate pre-load the pattern
Small / heavily quantized models 4-bit damages long-context behaviour first; loops on long inputs are a classic symptom
Broken stopping Wrong chat template, missing/incorrect EOS/stop tokens on self-hosted models → model keeps going

Part 1: mitigations and side effects

Knob What it does Typical values Side effect
presence_penalty Subtract a constant from logits of tokens already in the output -2..2 (OpenAI convention), default 0; ~0.1–1 to reduce Discourages legit re-use of terms
frequency_penalty Subtract proportional to count in output -2..2, default 0 Same, stronger for frequent tokens
repetition_penalty (vLLM/HF) Multiplicative; >1 penalizes tokens seen in prompt + output 1.0 default; CTRL paper suggested ~1.2 Pushes model away from source wording, IDs, JSON keys; can corrupt structured output
no_repeat_ngram_size (HF transformers) Hard ban: any n-gram only once 3–4 for short creative text Forbids legit repeated phrases
DRY sampler (llama.cpp, others) Penalizes extending an existing sequence; exponential in match length multiplier 0 = off, base 1.75, allowed length 2 Better targeted; not in every engine
temperature / top-p Add randomness to exit loops prose ~0.6–0.8 / 0.9; extraction low Higher temp adds variance
max_tokens, stop Cap damage size to task Doesn't prevent loop — monitor finish_reason == "length"
Pipeline fixes Dedupe inputs, fix chat template/EOS, sectioned generation, summarize agent history — Usually the real cure

Hosted reasoning models (e.g. OpenAI o-series / GPT-5 reasoning modes) often fix temperature and penalties; your levers are prompt, output budget, pipeline.

Example (vLLM OpenAI-compatible server, penalties for prose only):

from openai import OpenAI
client = OpenAI(base_url="http://vllm:8000/v1", api_key="x")

# Open-ended summary: gentle anti-repetition
summary = client.chat.completions.create(
    model="served-model",
    messages=[{"role": "user", "content": prompt}],
    temperature=0.7, top_p=0.9,
    presence_penalty=0.3, frequency_penalty=0.3,
    max_tokens=800, stop=["\n\n###"],
    extra_body={"repetition_penalty": 1.05},  # vLLM extension; keep near 1.0
)
if summary.choices[0].finish_reason == "length":
    metrics.increment("llm.length_capped")      # cheapest repetition alarm

# Extraction / JSON: no penalties, low temperature, schema-constrained
extract = client.chat.completions.create(
    model="served-model",
    messages=[{"role": "user", "content": extract_prompt}],
    temperature=0.0, max_tokens=400,
    response_format={"type": "json_schema", "json_schema": {"name": "fee", "schema": FEE_SCHEMA}},
)

Part 2: hallucination taxonomy

Type Example Primary defense
Faithfulness / intrinsic Source says fee is $15, answer says $12 Groundedness check, number verification
Factuality / extrinsic Invented policy clause, regulation number, court case Grounding + abstention + citation verification
Fabricated citation Well-formed citation to a nonexistent source Native citations returning exact spans; verify spans exist
Stale fact Last year's rate Fresh, versioned retrieval
Reasoning error True premises, wrong conclusion Self-consistency, verifier, code for arithmetic
Tool hallucination Nonexistent tool or invented argument (account ID) Strict tool schemas, enums, argument validation against system of record

Why: models can't always separate true from plausible-false statements, and training/benchmarks reward guessing over "I don't know" (Kalai et al., "Why Language Models Hallucinate", 2025). War-story shape: the widely reported 2023 court filing citing chatbot-invented cases — confident, well-formed, unverifiable.

Part 2: the layered defense

  1. Grounding (stack) — RAG with good chunking, hybrid retrieval, reranking, freshness/versioning, access control. Many "hallucinations" are retrieval misses.
  2. Abstention (writer's instructions) — "answer only from sources; say you can't find it" + measure abstention rate on unanswerable eval cases.
  3. Constrained output (dials) — low temperature, structured outputs (JSON schema compiled to grammar; available in OpenAI, Claude API, vLLM), enums, strict tool schemas.
  4. Citations — per-claim pointers; Claude API citations return cited_text spans guaranteed to reference supplied docs.
  5. Gate 1: mechanical verification — cited span exists and contains quoted number; entities/IDs match lookup tables.
  6. Gate 2: groundedness — NLI model or LLM judge per sentence; managed: AWS Bedrock Guardrails contextual grounding check (grounding + relevance scores with thresholds); Azure AI Content Safety groundedness detection (preview; QnA / summarization task modes, optional correction). Self-consistency / semantic entropy (Nature 2024) for high-stakes open questions (costs N× inference).
  7. Gate 3: human review — advice, credit/claims decisions, fee/entitlement statements, regulatory filings; route by risk; reviewer sees sources + scores.
  8. Monitoring + audit — log prompt, sources, settings, gate scores; track groundedness, abstention, length-capped rate, user flags; confirmed failures → eval set.

Key terms

Term Meaning
Autoregressive Each generated token is appended to the context for the next step
Self-reinforcement effect Repetition probability grows with prior repetitions
Induction head Attention circuit that copies "what followed this token last time"
Presence vs frequency penalty Flat vs count-proportional additive logit penalty on output tokens
Repetition penalty Multiplicative penalty over prompt + output tokens
DRY Sequence-extension penalty, exponential in repeat length
Faithfulness vs factuality Contradicts sources vs untrue/unsupported in the world
Groundedness Degree each claim is supported by provided context
Semantic entropy Uncertainty over meaning-clusters of multiple samples
Abstention Model declining to answer when evidence is insufficient

5 interview questions with strong answers

1. Why do LLMs repeat themselves? Autoregressive generation feeds output back as context; repetition is self-reinforcing (probability rises with each prior repetition), induction heads make copying cheap, and greedy/low-temperature decoding can't escape once the loop is the top choice. Long outputs, repetitive inputs, small/4-bit models and broken stop tokens amplify it.

2. How do you mitigate repetition without breaking extraction? Fix pipeline first (inputs, template/EOS, sectioned outputs, max tokens, stop sequences, alert on length-capped rate). Use moderate temperature/top-p and gentle presence/frequency penalties for prose only; keep repetition penalty ~1.0 for extraction and JSON because it penalizes prompt tokens and harms faithful quoting.

3. How do you handle hallucinations in a regulated assistant? Layers: fresh grounded retrieval, instructed and measured abstention, constrained outputs, per-claim citations, then mechanical verification, a groundedness gate with thresholds, and human review for advice/fee/credit outputs; log everything for audit and feed failures to evals.

4. Does temperature 0 eliminate hallucination? No — it removes sampling randomness, not missing knowledge; the model confidently emits its single most likely wrong answer, and at temperature 0 on long outputs you also raise loop risk.

5. How would you detect hallucinations at scale in production? Continuous groundedness scoring on sampled traffic (NLI/judge or managed guardrail), citation/number verification in code, self-consistency for high-stakes queries, user flags, and human-calibrated judges; track rates per intent and alert on drift.

The cloud platforms ship managed versions: on A W S, the Bedrock Guardrails contextual grounding check scores grounding and relevance against thresholds you configure; on Azure, the A I Content Safety service offers groundedness detection. Below threshold, you block, regenerate or route to a fallback. For ungrounded, open questions, there's a complementary trick: self-consistency. Sample the same question several times. If the model really knows the answer, the samples agree; if it's guessing, they scatter. Research in Nature in twenty twenty-four refined this into semantic entropy, clustering samples by meaning rather than wording. It costs several times the inference, so it's used selectively, on high-stakes answers. Gate three: human review for regulated outputs. Anything that constitutes advice, a credit or claims decision, a customer-facing statement of fees or entitlements, or a regulatory filing goes to a qualified human before it leaves the room, with the sources and the groundedness scores in front of them. Route by risk: low-risk internal answers flow through, high-risk ones queue for review. And log everything: the strip, the stack, the dial settings, the gate scores. In an audit, "what did the system see and why did it say that" must be answerable. Behind all three gates: monitoring. Sample production traffic, run the groundedness scorer continuously, track the abstention rate, the length-capped rate for repetition, and user flags, and feed every confirmed hallucination into the evaluation set. [PAUSE 2s] ## The interview angle When they ask "why do L L Ms repeat themselves and how do you mitigate it," a strong ninety-second answer sounds like: "Generation is autoregressive: every token the model writes goes back into its context. Repetition is self-reinforcing: studies show the probability of repeating a sentence rises with each time it has already appeared, and the copying mechanism behind in-context learning, induction heads, makes continuing a previous pattern very cheap. Greedy or very low-temperature decoding removes the randomness that would break the loop, and long outputs, repetitive inputs, small or heavily quantized models, and bad stop-token or chat-template setups all make it worse. Mitigations, in order: fix the pipeline, meaning clean inputs, correct templates, structured and sectioned outputs, a sensible max tokens, stop sequences, and monitoring of responses that hit the length cap. Then decoding: moderate temperature and top-p for prose, and gentle presence or frequency penalties. I'm careful with repetition penalty, because it also penalizes tokens from the prompt, which hurts faithful quoting and can corrupt structured output. So penalties go on for open-ended text and off for extraction and JSON." When they ask "how do you handle hallucinations," the strong answer: "Layers. Classify first: faithfulness errors contradict the sources, factuality errors invent things that aren't there. Ground the model with good, fresh retrieval, since many hallucinations are really retrieval misses. Instruct and evaluate abstention. Constrain the output with schemas and enums. Require citations to exact passages. Then verify after generation: code checks that cited passages and numbers exist, a groundedness scorer with a threshold, self-consistency for high-stakes open questions, and human review for regulated outputs like advice or fee statements. Monitor groundedness and abstention rates in production and feed failures back into the eval set." Likely follow-ups. "Does lowering temperature fix hallucination?" Trap: yes. Better: it reduces randomness, not ignorance; a model at temperature zero will confidently produce its single most likely wrong answer. "Can R A G hallucinate?" Yes: wrong or stale chunks, conflicting sources, or the model blending its prior knowledge with the context. "How would you measure hallucination rate?" A labeled set with a groundedness metric, calibrated against human judgment, which is exactly next episode's topic. [PAUSE 2s] ## Sixty-second recap Walk the table one last time.

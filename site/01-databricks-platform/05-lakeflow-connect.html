Track 1 · Databricks Platform & Data Engineering · Episode 5

Lakeflow Connect: Managed Ingestion & CDC

17 min listen · The harbor mental model of Databricks ingestion — managed SaaS connectors, the two-piece CDC gateway architecture for databases, Auto Loader and the DIY docks, and how to choose between them in an interview.

Facts verified: 2026-07-17 (Salesforce/Workday/SQL Server GA; gateway on classic compute in your VPC/VNet)

The mental model: the harbor

Sources = water · docks = ingestion tech · conveyors → bronze. Walk most-managed → most-manual.

flowchart LR
    subgraph Sources
      SF[Salesforce/Workday/ServiceNow]
      DB[(SQL Server / OLTP DBs)]
      FILES[Files → ADLS/S3 landing]
      K[Kafka / Event Hubs]
    end
    SF -->|managed SaaS connector| BR[Bronze streaming tables in UC]
    DB -->|"ingestion gateway (classic compute, YOUR VNet)\n→ CDC events → UC staging volume"| PIPE["ingestion pipeline (serverless)"] --> BR
    FILES -->|"Auto Loader\n(directory listing / file notification)"| BR
    K -->|structured streaming| BR

The docks

Dock Tech Key mechanics Use when
Ferry terminal Managed SaaS connectors (Salesforce, Workday GA; SQL Server GA; ServiceNow, GA4, Jira…) Databricks owns API pagination, rate limits, incremental cursors, schema drift. Config, not code Connector exists + covers your objects
Tanker berth Managed DB CDC connectors Two-piece: gateway (classic compute in your VPC/VNet, reads transaction log/CDC tables, stages to UC volume) + serverless ingestion pipeline (applies changes). Snapshot → CDC convergence handled DB replication at scale
— Query-based connectors Incremental pulls by cursor column, no CDC needed on source CDC can't be enabled
File beach Auto Loader (cloudFiles) Exactly-once via checkpoint; discovery: directory listing (simple, cost grows) vs file notification (Event Grid/S3 events, scales to millions); schema inference + evolution + _rescued_data Landing-zone files
Offshore pipeline Structured streaming Native Kafka/Event Hubs/Kinesis → bronze True streams
Rowboat COPY INTO Idempotent ad hoc loads One-offs only

Decision logic (interview)

  1. Managed connector exists → use it ("undifferentiated plumbing isn't where staff engineers spend innovation budget").
  2. DB replication → CDC connector (snapshot+CDC convergence = code you least want to own).
  3. Files → Auto Loader, notification mode past ~1000s files/day.
  4. Streams → structured streaming.
  5. Genuinely weird/governed sources → build (metadata-driven framework pattern — the classic build-your-own ingestion engine).

Pitfalls

  1. Gateway networking — gateway must reach DB: private endpoints, firewall, DNS. Budget the Infosec time.
  2. Source CDC retention vs gateway lag — gateway down longer than source log retention = gap = re-snapshot. Monitor lag like Kafka consumer lag.
  3. Checkpoint amnesia — Auto Loader checkpoint IS ingestion memory; deleting it = reload or skipped files. Treat as state.
  4. Schema drift by default — decide per pipeline: evolve / rescue / fail. Silent evolution forks columns.

Interview Q&A

Q1. Design enterprise ingestion on Databricks. Walk the harbor: SaaS → managed connectors; DBs → CDC connector (gateway in my network, staging volume, serverless apply); files → Auto Loader notification mode with explicit schema policy; streams → structured streaming. All land as bronze STs in UC — governance from the waterline. Name ops realities: gateway network path, CDC retention vs lag, checkpoint discipline.

Q2. How does the managed CDC connector work? Two pieces: ingestion gateway on classic compute inside customer VPC/VNet reads source change log continuously → stages raw events in UC volume; serverless ingestion pipeline applies ordered changes to Delta. Initial snapshot then CDC convergence, exactly-once.

Q3. Auto Loader directory listing vs file notification? Listing: periodic list + checkpoint diff — simple, list cost grows with directory. Notification: storage events (Event Grid/S3) push new-file events — scales to millions, needs event infra permissions.

Q4. When would you still build custom ingestion? No connector for source (bespoke protocols, network elements), extreme governance constraints, or transformation-at-ingest needs. Pattern: config/metadata-driven single engine, not per-source scripts.

Q5. Managed connector vs your own framework — tradeoff? Managed: zero maintenance, fast onboarding, opaque internals, connector coverage limits. Custom: full control, any source, but you own snapshot/CDC/drift/retries forever. Buy the commodity, build the differentiated.

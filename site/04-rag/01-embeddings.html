Track 4 · RAG · Episode 1

Embeddings & Vector Similarity from First Principles

20 min listen · The map of meaning that every R A G system stands on: what an embedding actually is, how a model learns to place text on that map, why cosine similarity is really about angles, and what dimensions, cost, and model swaps do to you in production.

Facts verified: 2026-09-25

One-sentence thesis

An embedding is a fixed-length vector produced by a contrastively trained model so that texts humans treat as related point in similar directions. Retrieval quality, cost, and the most common silent failures (model mismatch, uncalibrated thresholds, weak exact-match recall) all follow from that geometry.

Track 4 roadmap

  1. Embeddings (this episode) → 2. Chunking → 3. Retrieval (BM25, hybrid, reranking, rewriting) → 4. Vector DB internals (HNSW, IVF, quantization) → 5. Advanced RAG → 6. RAG evaluation → 7. Production failure modes → 8. Drill.

The mental image: the map of meaning

  • A huge map on a table; every text is a pin. Cooking pins cluster on the left, finance on the right, software errors at the top, travel at the bottom.
  • From a center point (origin), an arrow runs to every pin. Direction = meaning. Similar texts have arrows pointing the same way.
  • Hovering above: the machine (embedding model) that drops pins. Queries go through the same machine; search = find the arrows pointing most nearly the same way.
  • Real maps have 384–3,072+ axes, not 2. The geometry is the same.
flowchart LR
    D["Documents / chunks"] --> E["Embedding model (transformer + pooling)"]
    Q["User question"] --> E
    E --> DV["Document vectors (stored in index)"]
    E --> QV["Query vector"]
    QV --> S{"Similarity: cosine / dot / L2"}
    DV --> S
    S --> K["Top-k nearest chunks"]
    K --> LLM["LLM answers with evidence"]

How embedding models are trained (contrastive learning)

flowchart TB
    P["Positive pair: question + its answer passage"] --> PULL["Pull vectors together"]
    N["In-batch negatives: other passages in batch"] --> PUSH["Push vectors apart"]
    PULL --> MAP["Map organises by topical relatedness"]
    PUSH --> MAP
    MAP --> GOOD["Strong: paraphrase, synonyms"]
    MAP --> WEAK["Weak: exact codes, IDs, rare names"]

Similarity metrics

Metric Measures Note
Cosine similarity Angle between vectors (ignores length) 1 = same direction, 0 = orthogonal
Dot product Direction and length Equals cosine when vectors are unit-length
Euclidean (L2) Distance between vector tips Same ranking as cosine for unit-length vectors

Rule: use the metric the model was trained with; if vectors are normalised (OpenAI embeddings are returned normalised), all three rank identically, so pick whatever your store is fastest at.

import numpy as np

def normalize(v):
    return v / np.linalg.norm(v, axis=-1, keepdims=True)

docs = normalize(doc_vectors)      # shape (N, d), do once at write time
q = normalize(query_vector)        # shape (d,), every query
scores = docs @ q                  # dot product == cosine for unit vectors
top_k = np.argsort(-scores)[:10]

Matryoshka truncation (OpenAI dimensions parameter):

from openai import OpenAI

3,072 ~12 KB ~123 GB
  • text-embedding-3-large: ~$0.13 per 1M input tokens; Batch API ~50% off. Embedding 100M tokens ≈ tens of dollars. The expensive part is re-embedding time, not money.
  • Model choice: use MTEB as a filter (open-weight Qwen3-Embedding models sit at/near the top of MTEB multilingual; Gemini, Voyage, Cohere, OpenAI are the main commercial options), but some commercial models are scored on only a fraction of tasks. Decide on your own labelled question set.

Pitfalls

  1. Mixing maps: vectors from different models are not comparable. Model name/version is part of index identity. Change model → parallel index, full re-embed, evaluate, atomic cutover (blue-green).
  2. Exact-match weakness: codes, SKUs, rare names → add BM25 (episode 3), enrich chunks (episode 2), or fine-tune.
  3. Multi-topic passages: one vector averages topics → pin lands between clusters → chunking.
  4. Truncation: inputs beyond the model's max length (≈512 to 8K+ tokens) are often silently cut.
  5. Uncalibrated scores: cosine 0.8 ≠ 80% relevant; thresholds must be re-tuned per model.
  6. Asymmetric models: some require query/document prefixes or instructions; skipping them silently degrades recall.

Key terms

Term Meaning
Embedding Fixed-length vector representing text meaning
Bi-encoder Encodes query and document separately (enables precomputation)
Mean pooling Averaging token vectors into one text vector
Contrastive learning Train by pulling positives together, pushing negatives apart
In-batch negatives Other examples in the batch used as negatives
Normalisation Scale vector to unit length
Matryoshka (MRL) Training so prefixes of the vector remain useful; enables truncation
MTEB Massive Text Embedding Benchmark
Recall@k Fraction of relevant items found in top k

5 interview questions

Q1. What is an embedding and what does cosine similarity measure? A fixed-length vector from a contrastively trained model where related texts point in similar directions. Cosine measures the angle between vectors, ignoring magnitude. With unit-normalised vectors, cosine, dot product and L2 give identical rankings.

Q2. How do you choose an embedding model? Build a labelled eval set from real queries; shortlist via MTEB; compare recall@k on your data; weigh dimensions vs memory, Matryoshka support, max input length vs chunk size, language coverage, and API vs self-hosted (residency, cost at volume, deprecation risk).

Q3. What happens when you switch embedding models? Everything must be re-embedded, since spaces aren't comparable. Build a parallel index, re-embed, evaluate, then switch queries and documents together. Store the model ID with the index to catch mismatches. Budget hours to days for large corpora.

Q4. Why does vector search miss exact identifiers like error codes? Contrastive training organises by topical similarity; near-identical strings in near-identical contexts get near-identical vectors. Lexical search (BM25) weights rare exact terms heavily, so hybrid retrieval covers the gap.

Q5. Can you set a global similarity threshold like 0.75? Not portably. Score distributions differ per model (some crowd into a narrow cone), so thresholds must be calibrated per model on labelled data and re-calibrated on every model change.

Track 7 · Transformer Architecture · Episode 2

Self-Attention Mechanics: Q, K, V by Analogy

17 min listen · Self-attention with no equations read aloud: every word tile raises a question flag, wears a label, and carries a bucket of content — flags match labels, scores become a pie of percentages, and each tile walks away with a weighted blend of buckets. Plus scaling, the causal curtain, and why the grid of scores is the memory problem.

Facts verified: 2026-09-25

One-sentence thesis

Self-attention lets every token build a context-aware version of itself: its query is compared with every token's key, the scaled similarity scores become softmax weights, and the output is the weighted sum of the tokens' values — computed for all tokens at once, which is both why it's fast on GPUs and why it costs O(n²).

The mental image: flag, label, bucket

  • Shelf of tiles (the sequence), left to right.
  • Flag above each tile = query: "what am I looking for?"
  • Label on each tile's front = key: "what do I offer?"
  • Bucket below each tile = value: "what I hand over if chosen."
  • All three are made from the same tile by three learned lenses (W_Q, W_K, W_V).
  • Flag held against every label → match scores → pie (softmax, sums to 100%) → pour that share of every bucket → new tile.
  • The grid of flags × labels floating above the shelf = the n × n score matrix = the quadratic cost.
  • Curtain hiding everything to a tile's right = causal mask → keys/values of past tokens never change → KV cache.
flowchart LR
    X["Token embeddings X (n x d)"] --> Q["Q = X W_Q (flags)"]
    X --> K["K = X W_K (labels)"]
    X --> V["V = X W_V (buckets)"]
    Q --> S["Scores = Q K^T / sqrt(d_k) (n x n grid)"]
    K --> S
    S --> M["Causal mask (decoder): -inf above diagonal"]
    M --> P["Softmax per row (the pie)"]
    P --> O["Output = P V (weighted blend of buckets)"]
    V --> O

The math (for reading, never read aloud)

Attention(Q, K, V) = softmax( Q Kᵀ / √d_k  +  M ) V

Q = X W_Q,  K = X W_K,  V = X W_V          X: (n × d_model), W_*: (d_model × d_k)
M_ij = 0 if j ≤ i else −∞                   (causal mask, decoder-only)

Why √d_k: if q and k components are ~independent with variance 1, q·k has variance d_k. Dividing by √d_k restores unit variance so softmax does not saturate (near one-hot → vanishing gradients).

import torch, math

def causal_self_attention(x, Wq, Wk, Wv):
    # x: (n, d_model)
    q, k, v = x @ Wq, x @ Wk, x @ Wv            # (n, d_k)
    scores = q @ k.T / math.sqrt(q.shape[-1])    # (n, n)  <- the quadratic grid
    n = x.shape[0]
    mask = torch.triu(torch.ones(n, n, dtype=torch.bool), diagonal=1)
    scores = scores.masked_fill(mask, float("-inf"))  # the curtain
    weights = scores.softmax(dim=-1)             # the pie, each row sums to 1
    return weights @ v                           # pour the buckets

# In practice: torch.nn.functional.scaled_dot_product_attention(q, k, v, is_causal=True)
# dispatches to FlashAttention-style fused kernels where available.

Worked example (the "it" tile)

Sentence: The animal didn't cross the street because it was too tired. Illustrative weights for "it" in one head (causal, so "tired" is hidden): animal 0.60, street 0.10, it 0.08, because 0.06, others small → output ≈ mostly the value of "animal". Other heads/layers refine further; later tiles ("tired") can see "it" and "animal".

Costs and numbers

Context n Scores per head per layer Naive fp16 memory for the grid
1K ~1M ~2 MB
32K ~1.07B ~2 GB
128K ~17B ~34 GB

FlashAttention (2022): tiles Q/K/V blocks into on-chip SRAM with an online softmax — exact result, memory O(n) instead of O(n²), fewer HBM reads/writes → large wall-clock speedups. Compute stays O(n²·d).

Pitfalls

  • Attention dilution at long context: the relevant token's slice gets crowded out → "lost in the middle" behavior; better retrieval often beats bigger context.
  • Attention sinks: softmax must sum to 1, so models park spare attention on the first token(s). Streaming/eviction schemes that drop the first tokens degrade badly; StreamingLLM keeps them.
  • Attention ≠ explanation: attention weights frequently don't track feature importance (Jain & Wallace 2019). Use perturbation/ablation or attribution methods to explain decisions.

5 interview questions

Q1. Explain self-attention simply. Each token asks a question (query), advertises a label (key), and carries content (value). It compares its query against every key, turns the scores into percentages with softmax, and takes that percentage of every value. Technically: learned Q/K/V projections, scaled dot-product, softmax, weighted sum of V.

Q2. Why separate Q and K projections instead of comparing embeddings directly? What a token looks for differs from what it offers; separate projections make the relation asymmetric and let each head learn a different relation type. Comparing raw embeddings would only capture symmetric similarity.

Q3. Why scale by √d_k? Dot-product variance grows with d_k; large scores saturate softmax to near one-hot, which kills gradients and prevents blending. Scaling keeps it soft and trainable.

Q4. What's the complexity and what does FlashAttention change? O(n²·d) compute and naive O(n²) memory for the score matrix. FlashAttention tiles computation in SRAM with an online softmax: exact output, O(n) extra memory, far fewer HBM round-trips → faster; compute remains quadratic.

Q5. Do attention weights explain a model's decision? Not reliably — information is mixed across many heads and layers, and alternative attention distributions can give the same prediction. Test explanations by ablation/perturbation (remove the "important" tokens and see if the output changes).

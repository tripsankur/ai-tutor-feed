Prompt Engineering Patterns That Matter in Interviews

17 min listen · The prompt patterns that still matter in twenty twenty-six, and the shift from prompt engineering to context engineering: one page, a fixed attention budget, and a disciplined order for everything you put on it, plus structured outputs, caching, reasoning models, and prompt injection.

Facts verified: 2026-09-25

Thesis: In 2026 prompt engineering is less about magic wording and more about context engineering — deciding what goes into a finite, degrading attention budget at every step, in what order — plus treating prompts as versioned, evaluated, cached, and defended production artifacts.

Patterns cheat sheet

  1. Clear instructions + motivation — explain why ("output is read by TTS, so never use ellipses"); the model generalizes from reasons.
  2. Structure — headings or XML-style tags separating instructions, context, examples, input.
  3. Few-shot — 3–5 diverse examples; models copy surface features (length, topics).
  4. Long-context ordering — documents at top, query at end: Anthropic reports up to ~30% quality improvement in tests on complex multi-doc inputs. Ask for relevant quotes first.
  5. Reasoning — classic models: chain of thought, with reasoning and answer in separate tagged sections. Reasoning models: don't say "think step by step" (OpenAI guidance); give constraints + success criteria; tune reasoning effort.
  6. Structured outputs — JSON Schema + constrained decoding (OpenAI strict: true; Anthropic structured outputs GA on Claude Developer Platform and Amazon Bedrock). Prefilling the last assistant turn is not supported from Claude 4.6-generation models (returns 400) — use structured outputs / tools / instructions.
  7. Prompt chaining — split only when stages can be evaluated/cached independently; try the single clear prompt first.
  8. Dial back aggression — newer models follow system prompts closely; "CRITICAL: you MUST…" causes over-triggering.

Context engineering (long-running agents)

  • Right altitude system prompt (not brittle if/else lists, not vague platitudes).
  • Tool hygiene: "if a human engineer can't definitively say which tool to use, the agent can't either."
  • Just-in-time retrieval: keep identifiers (paths, titles, queries), load content on demand; hybrid = small preloaded core + on-demand fetch.
  • Compaction: summarize history near the limit, keep decisions/open issues, drop redundant tool outputs.
  • Structured note-taking: persistent notes/to-do/progress files outside the window.
  • Sub-agents: focused work in a clean context; return a condensed summary (thousands of tokens explored → ~1–2k returned).

War story

A system prompt carried a to-the-second timestamp on line one. Unique prefix per request → prompt cache never hit → long static prompt + tool definitions billed at full price every call. Moving the (day-granularity) date to the bottom restored cache hits and cut input cost by more than half.

5 interview questions

1. What prompt engineering techniques actually matter? Clear system prompt at the right altitude with reasons for constraints; labeled structure; long documents above the query and quote-grounding; 3–5 diverse examples; schema-constrained structured outputs; CoT for classic models vs success criteria + effort for reasoning models; and versioning + eval gating for every prompt change.

2. Prompt engineering vs context engineering? Prompt engineering = writing instructions. Context engineering = managing everything in the context window at each step of an agent under a finite attention budget: minimal unambiguous tools, just-in-time retrieval, compaction, external notes, sub-agents with clean contexts.

3. How do you get reliable JSON out of an LLM? Use provider structured outputs (JSON Schema with constrained decoding / strict mode) or tool calling, not "please return JSON" + retry parsing. Validate downstream anyway. Don't rely on prefill (unsupported on newest Claude models).

4. How do you defend against prompt injection? Not solvable in the prompt alone (instructions and data share one channel). Delimit and label untrusted content, but rely on architecture: least-privilege tools, human approval for consequential actions, output validation/sanitization, separating untrusted-content readers from tool-holding agents, and no secrets in system prompts.

5. How does prompt design affect cost and latency? Order: static prefix (system prompt, tools, stable docs) first so it caches (≈90% discount on cached reads on current Anthropic/OpenAI flagships); dynamic content last. Keep tool definitions and outputs lean; compact history; avoid over-long few-shot sets; prefer reasoning effort settings over verbose CoT instructions.

Continuous batching lets new requests join the running batch at every generation step instead of waiting for the whole batch to finish. Together they drive much higher throughput on the same hardware. [PAUSE 2s] Question eight. What's speculative decoding, and when doesn't it help? [PAUSE 6s] Strong answer: a small draft model, or extra prediction heads, proposes several tokens ahead, and the large model verifies them in a single forward pass, accepting the ones it agrees with, so output quality is unchanged. It speeds up decoding when the draft is usually right and the system is memory-bound; it helps less under heavy batch load or when the draft's acceptance rate is low. [PAUSE 2s] Question nine. Operational metrics on every request through tracing: time to first token, p ninety-five and p ninety-nine latency, tokens and cost per request by feature, and error, timeout and schema-failure rates. Quality on a sample plus every flagged trace, with code checks and calibrated L L M judges for groundedness, relevance and safety. [PAUSE 6s] Strong answer: input drift, the query mix shifting, caught with embedding clusters and intent frequencies. Model drift, a version or alias change, prevented by pinning snapshots and eval-gating upgrades. [PAUSE 2s] Question twelve. What's the difference between prompt engineering and context engineering? [PAUSE 6s] Strong answer: prompt engineering is writing good instructions. That means minimal, unambiguous tools, just-in-time retrieval instead of pre-loading, compaction of history, notes stored outside the window, and sub-agents with clean contexts.

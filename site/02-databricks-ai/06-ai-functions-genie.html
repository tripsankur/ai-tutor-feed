AI Functions in SQL, Genie, AI/BI

17 min listen · AI Functions bring the L L M to the sequel analyst's own counter through ai_query, while Genie is the multilingual concierge that turns a business user's plain-English question into governed sequel — with the 2026 evolution into Genie One, Genie Ontology, and Genie Agents.

Facts verified: 2026-07-22 (ai_query requirements, Genie GA, Genie One / Genie Ontology / Genie Agents launched at Data + AI Summit 2026)

One-sentence thesis

Two front-of-house moves put the L L M to work without leaving governed sequel: ai_query is the intercom from a sequel statement straight to a serving endpoint (batch inference, no Python); Genie is the concierge who takes a plain-English question and writes governed sequel for you — and in 2026 that concierge got promoted into Genie One, Genie Ontology, and Genie Agents.

ai_query — the shape of it

-- Batch sentiment classification over a million support tickets, no Python
SELECT ticket_id,
       ai_query(
         'my-llm-endpoint',
         CONCAT('Classify sentiment as angry, neutral, or happy: ', ticket_text)
       ) AS sentiment
FROM silver.support_tickets;

-- Task-specific function: structured field extraction
SELECT contract_id,
       ai_extract(contract_text, array('effective_date', 'renewal_date', 'contract_value'))
FROM silver.contracts;

Tradeoffs to volunteer

  1. ai_query cost/throughput risk — a model call per row adds up; an endpoint sized for interactive traffic can be overwhelmed by an uncoordinated batch job. Batch sensibly, watch endpoint throughput, provision ahead of known large jobs.
  2. Genie grounding is a design discipline, not a model property — war story: two tables both with a column called "revenue" (net vs gross), no distinguishing instruction, Genie picked one and answered confidently wrong. Fix was scoping the space + writing the instruction down, not a smarter model.
  3. Genie One / Genie Agents still need golden-question regression testing — agentic and multi-surface capability doesn't remove the need for eval gates before an agent sends a report to an executive unsupervised.
  4. Dashboard vs Genie — reach for Genie when the question hasn't been asked before; reach for the A I/B I dashboard when it's asked every week.

Interview Q&A

Q1. How would you let business analysts run L L M-powered enrichment over a table without writing Python? ai_query() called directly from the sequel statement they already write — serverless batch inference, handles parallelization/retries/scaling automatically, governed by the same Unity Catalog grants as the source table. Reach for task-specific functions (ai_classify, ai_summarize, ai_extract, etc.) first since they're pre-tuned; drop to general-purpose ai_query for anything bespoke. Name the three real limits: serverless-only, Databricks Runtime 18.2+, supported Model Serving region.

Q2. A non-technical business user needs an answer — what's the path? Genie: a Genie space scoped to a curated set of tables, grounded with written instructions and trusted/certified sample queries, compiles the plain-English question to read-only sequel. Cite the benchmark: 84.5% first-attempt accuracy vs 52.4% for a general coding agent, roughly 2x faster, because it's briefed and grounded rather than guessing schema from scratch.

Q3. How does Genie avoid hallucinating table names or joins? Grounding via the Genie space: a narrow, curated table set, plain-language instructions capturing business semantics ("revenue means net revenue from the finance mart"), and trusted/certified sample questions to pattern-match against. Grounding is something an analyst designs into the space — not an emergent property of the model.

Q4. Where does Genie One fit versus a hand-built agent? Genie One is the fast path for structured plus unstructured data already registered in the lakehouse — agentic beyond Q&A (documents, reports, artifacts), multi-surface (web/iOS/Android), scheduling/alerts, native M C P tool integration. Hand-build an agent when you need bespoke tool orchestration or logic that doesn't reduce to "ask a governed question, get an answer."

Q5. How does Genie decide which of 50+ connected systems to trust for an answer? It isn't decided per question — Genie Ontology maintains a continuously updated graph of how company data and connected applications relate, ahead of time. Grounding shifts from question-time guessing to design-time curation.
